# Install NetP2P managers

Deploy a three-manager committee with Docker Compose and enroll your first client.

## Outcome

Three manager containers running behind Caddy, a certified network, and a working
owner account on the web console.

## Prerequisites

- Three Linux hosts (amd64 or arm64) with Docker Engine and the Docker Compose plugin.
- DNS A records pointing each manager hostname to its public IPv4, and a round-robin
  record for the console entry. Use direct (grey-cloud) DNS; do not proxy UDP paths
  through a CDN.
- Outbound internet access for container image pulls and certificate issuance.
- A network seed and per-manager bundles generated by your provisioning flow.

## Network exposure

| Port | Protocol | Exposure |
| --- | --- | --- |
| 4001/udp | public | libp2p QUIC control and data |
| 4101/udp | public | WebRTC and bootstrap |
| 9443/tcp | public | HTTPS via Caddy |
| 18080/tcp | loopback | manager web listener |
| 9101/tcp | restricted | Prometheus metrics |

Open UDP 4001 and 4101 and TCP 9443 in your cloud security group. Restrict TCP 9101
to your monitoring host.

## Steps

### 1. Create directories

On each manager host:

```bash
sudo mkdir -p /opt/netp2p /etc/netp2p /var/lib/netp2p
sudo chown 999:999 /var/lib/netp2p
```

### 2. Render configuration

Place the runtime configuration, seed-derived manager bundle, and Caddyfile under
`/etc/netp2p/`. Use an infrastructure tool such as Ansible to keep the three hosts
consistent. The manager container runs read-only as `999:999` without
`NET_ADMIN`; Caddy terminates HTTPS on 9443 and proxies to `127.0.0.1:18080`.

Pin images by digest, not by tag:

```yaml
image: ghcr.io/zhongwwwhhh/netp2p-manager@sha256:<digest>
```

### 3. Pre-pull and start all together

Because a 3-of-3 committee needs every member to accept writes, start all three
at the same time:

```bash
# on each host
docker compose pull
docker compose create --force-recreate
```

Then start all three within your maintenance window:

```bash
docker compose start
```

### 4. Create the owner

Open the console at `https://console.netp2p.example:9443/`. When no owner exists,
the console shows the owner-creation form. Create the owner with a valid email
(for example `owner@example.com`) and a password of at least 12 characters.

Only one owner bootstrap is possible. Keep the password in a password manager;
there is no self-service recovery.

### 5. Create a setup key

In the console, go to **Setup keys** and create a one-off key with an expiry and
target group. The token is shown once. Copy it to a protected file on the client.

## Validation

Check readiness on each manager:

```bash
curl -fsS https://manager-1.netp2p.example:9443/readyz
curl -fsS https://manager-2.netp2p.example:9443/readyz
curl -fsS https://manager-3.netp2p.example:9443/readyz
```

Require HTTP 200, `ready`, equal BFT heights, and `3/3` committee connectivity.
`/healthz` only proves the process is alive.

Then enroll a client per the [client guides](../clients/index.md) and verify
bidirectional connectivity with `netp2p ping`.
